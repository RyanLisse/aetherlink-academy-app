Ask the Council a Question

What this project does, and what happens between typing a question and getting a verdict back

One question, four opinions, one verdict

This project is a small starter for an idea called an LLM council: instead of asking one LLM once, you ask several "members" the same thing, then let a judge boil their answers down into one final answer plus a score for how much each member agreed.

It was built for AetherLink Academy's Agent Arcade as a lab exercise, using the Claude Agent SDK.

1
You ask a question

"Moeten we een paraplu meenemen in Amsterdam?" (Should we bring an umbrella in Amsterdam?)

2
Fan-out: four members answer

Alpha, Bravo, Charlie and Delta each give an opinion.

3
Reduce: the judge decides

One short summary, plus an agreement score from 0 to 1 for each member.

Fan-out, then reduce

Sending one job to many workers and then combining their results is one of computing's oldest patterns. Engineers call it fan-out / reduce (you may hear "map-reduce"). Knowing the name lets you ask an AI for it directly: "fan this out to three reviewers and reduce to one verdict."

These members are actors reading a script

No AI is called here. The answers are fixtures: fixed sentences with your question pasted in. That keeps the lab free and the tests predictable.

Where the script lives

The whole council is one function in src/council.ts that returns a list of four answers.

src/council.ts 
/** Fixture member answers — no live multi-model spend. */
export function fanOutFixture(prompt: string): CouncilMemberOutput[] {
  const base = prompt.trim() || 'Geen prompt';
  return [
    { id: 'alpha', answer: `Alpha: ${base} — focus op feiten.` },
    { id: 'bravo', answer: `Bravo: ${base} — misschien, hangt van context af.` },
    { id: 'charlie', answer: `Charlie: ${base} — concrete stappen: 1) check bron 2) beslis.` },
    { id: 'delta', answer: `Delta: ${base} — eens met Charlie over broncheck.` },
  ];
}

The ballot form every member fills in

Think of an election ballot: every voter gets the same printed form with fixed boxes, so counting is easy. src/schemas.ts is that printed form. It uses TypeScript types to describe the exact shape of every answer and every verdict.

src/schemas.ts 
export type CouncilMemberId = 'alpha' | 'bravo' | 'charlie' | 'delta';

export type CouncilMemberOutput = {
  id: CouncilMemberId;
  answer: string;
};

export type JudgeResult = {
  answer: string;
  agreement: Record<CouncilMemberId, number>;
  notes: string;
};

export const MEMBER_IDS: CouncilMemberId[] = ['alpha', 'bravo', 'charlie', 'delta'];
PLAIN ENGLISH

A member name can only be one of these four words. "echo" would be rejected.

A member's ballot has exactly two boxes:

who they are,

and what they said.

The judge's verdict has three boxes:

the final answer,

a score for every one of the four members (a lookup table: name to number),

and a short note about which rule was used.

The official roll call, in order. The judge walks this list when scoring.

💡
Structured output beats free text

Because the verdict is a fixed schema, other code (tests, dashboards, a grading bot) can read agreement.bravo without guessing. When you ask an AI for results, asking for "JSON matching this schema" is what makes them usable by software.

The Judge's Scorecard

How the reduce step picks a winner and turns words into numbers between 0 and 1

Scored like figure skating

A figure skating judge starts from a base value, adds bonuses for clean elements, subtracts deductions for falls, and the final mark can never drop below zero. This judge works exactly the same way, except its "elements" are words.

0.55

Everyone starts with the same base score

→
+0.2

Bonus for concrete words: feit, bron, concreet, stappen

→
−

Deduction for vague words: misschien, hangt, vague, vaag

→
+0.1

Bonus for sharing a long word with the final answer

→
0–1

Clamp into the 0 to 1 range and round

The scoring function, line by line

This is scoreAgainstJudge in src/council.ts. It uses regular expressions to spot words, and a boolean called strict to decide how harsh the vagueness penalty is.

src/council.ts 
function scoreAgainstJudge(member: CouncilMemberOutput, judgeAnswer: string, strict: boolean): number {
  const text = member.answer.toLowerCase();
  let score = 0.55;
  if (/feit|bron|concreet|stappen/.test(text)) score += 0.2;
  if (/misschien|hangt|vague|vaag/.test(text)) score -= strict ? 0.35 : 0.15;
  if (judgeAnswer.toLowerCase().split(/\s+/).some((w) => w.length > 4 && text.includes(w))) score += 0.1;
  return Math.max(0, Math.min(1, Number(score.toFixed(2))));
}
PLAIN ENGLISH

To score one member, I need their answer, the judge's final answer, and whether strict mode is on.

Lowercase the member's answer so "Bron" and "bron" count the same.

Start at 0.55.

Mentions facts, sources, concreteness or steps? Add 0.2.

Uses hedging words? Subtract 0.35 when strict, only 0.15 when mild.

Chop the final answer into words. If any word longer than 4 letters also appears in this member's answer, add 0.1.

Round to two decimals and squeeze the result so it never goes below 0 or above 1.

Done.

A bonus everybody always gets

Every fixture member repeats your question, and the final answer repeats it too. So the "+0.1 overlap" bonus fires for all four members on almost every question. A check that always passes measures nothing. Spotting this kind of thing is exactly how you catch an AI-written heuristic that looks clever but does not discriminate.

Picking the winning answer

04

Rules Written in Prose

How a Markdown file steers the judge, and the mini-quest that asks you to edit it

A note on the fridge for the house-sitter

You leave a note for a house-sitter who does not read full sentences. They skim for a few magic words: see "strenger" and they get strict, see "Nederlands" and they speak Dutch, see "max 80 woorden" and they keep it short. Everything else on the note is decoration to them.

That note is instructions.md, a plain Markdown file. The house-sitter is loadJudgeRule.

instructions.md 
## Judge / reduce (mini-quest hook — edit this section)
You are the **rechter** (judge). Produce:
1. A short final answer (max 80 woorden, Nederlands tenzij de gebruiker Engels vraagt).
2. Per-member agreement scores from 0 to 1 (how well each member supports the final answer).

### Judge rule (edit for mini-quest)
Wees strenger bij vage claims. Prefer concrete statements. If members disagree, say so explicitly and lower agreement scores for vague answers.
PLAIN ENGLISH

A heading marking the part you are allowed to edit.

Contains "rechter": the quest script checks this word exists.

"max 80 woorden" sets the word limit. "Nederlands" switches the answer to Dutch.

Describes the scores. Human-readable only; the code ignores it.

The quest's target zone.

"strenger" (stricter) is the switch that turns on the harsh 0.35 vagueness penalty.

The house-sitter, in code

loadJudgeRule reads the whole note and returns three settings. Watch the \b markers: they mean "word boundary", so the word must stand on its own.

src/council.ts 
export function loadJudgeRule(instructions: string): { strict: boolean; dutch: boolean; maxWords: number } {
  const strict = /\bstrenger\b|\bbe strict\b|strict-vague/i.test(instructions);
  const dutch = /nederlands/i.test(instructions);
  const maxMatch = instructions.match(/max\s*(\d+)\s*woord/i);
  const maxWords = maxMatch ? Number(maxMatch[1]) : 80;
  return { strict, dutch, maxWords };
}
PLAIN ENGLISH

Take the note's full text; return three settings: strict yes/no, Dutch yes/no, and a word limit.

Strict if the note contains the standalone word "strenger", the phrase "be strict", or "strict-vague". Capital letters do not matter.

Dutch if "nederlands" appears anywhere at all.

Look for "max", a number, then "woord". Remember the number.

Found one? Use it. Otherwise default to 80 words.

Hand the three settings back.

Done.

💡
Prose as configuration

The same file is a system prompt for a real model (module 5) and a config file for the fixture judge. That is elegant, but keyword matching is brittle: a rephrasing a human reads as identical can flip a setting in code. When you ask an AI to "read settings from a prompt file", ask it to list which exact words it matches.

05

Rehearsal vs Live

The free fixture path, the paid Claude Agent SDK path, and the tests that keep both honest

Flight simulator, then real plane

Pilots log hours in a simulator first: same cockpit, same controls, no fuel burned, no risk. This project has the same split. Everything you have seen so far is the simulator.

🕹️

Fixture path: runCouncil

Scripted members, rule-based judge. Free, instant, identical every run. Used by npm start without a key and by every test.

✈️

Live path: runCouncilAgentLive

Sends your question to Claude through the Agent SDK, with instructions.md as its standing orders. Needs a key and costs money.

The live path, in code

This function in src/agent.ts calls query() from the Claude Agent SDK. It is async because Claude's reply arrives over the network as a stream of messages.

src/agent.ts 
/** Optional live SDK path — single model asking to apply judge instructions (env key required). */
export async function runCouncilAgentLive(prompt: string) {
  if (!process.env.ANTHROPIC_API_KEY) {
    throw new Error('Set ANTHROPIC_API_KEY in the environment. No secrets in git.');
  }
  const instructions = loadInstructions();
  const messages: unknown[] = [];
  for await (const message of query({
    prompt: `${prompt}\n\nApply the council judge instructions and return JSON with answer + agreement scores.`,
    options: {
      systemPrompt: instructions,
      permissionMode: 'bypassPermissions',
    },
  })) {
    messages.push(message);
  }
  return messages;
}
PLAIN ENGLISH

Honest label: this is one model, not a real four-member council.

Define the live function. It takes the question and works asynchronously.

No API key in the environment?

Stop immediately with a clear error. Never paste keys into code.

Read instructions.md as text.

Prepare an empty list to collect Claude's messages.

Start a conversation with Claude and handle each message as it streams in:

the question, plus a request to judge it and reply in JSON,

with these settings:

the instructions file becomes Claude's system prompt,

and Claude may use tools without asking for approval each time.

Drop every incoming message into the list.

Return the full transcript.

Done.

⚠️
Read the label, not the function name

runCouncilAgentLive uses one model as the judge, not four council members. npm start calls it only when ANTHROPIC_API_KEY is set. Count the SDK calls instead of trusting a function name. The bypassPermissions setting skips tool approval, so do not use it with access to real files or data.

Tests that keep your quest edit in place

The project's tests run with Node's built-in test runner. The judge test uses short rule samples in memory. It does not change instructions.md, so you can run it after your quest.

tests/council-reduce.test.ts 
test('judge instruction delta changes reduce notes', () => {
  const strictRule = 'Wees strenger bij vage claims.';
  const mildRule = 'Wees mild; vague wording is fine.';
  const a = loadJudgeRule(strictRule);
  const b = loadJudgeRule(mildRule);
  assert.equal(a.strict, true);
  assert.equal(b.strict, false);
  const members = fanOutFixture('Vague topic');
  const strictJudge = reduceCouncil({ prompt: 'x', members, instructions: strictRule });
  const mildJudge = reduceCouncil({ prompt: 'x', members, instructions: mildRule });
  assert.equal(strictJudge.notes, 'judge-rule:strict-vague');
  assert.equal(mildJudge.notes, 'judge-rule:default');
  assert.ok(strictJudge.agreement.bravo <= mildJudge.agreement.bravo);
});
PLAIN ENGLISH

The test checks how changing the rule changes the result.

Set one short sample rule to strict.

Set another sample rule to mild.

Read the settings from each sample.

Assert the first is strict...

...and the second is not.

Get the four scripted members.

Judge them with the strict rules...

...and with the mild rules.

The strict verdict must carry the strict label...

...and the mild one the default label.

Bravo must never score higher under strict rules than mild ones.

End of test.

💡
Tests leave your file alone

The judge test passes sample text to loadJudgeRule. It does not write to instructions.md, so the test cannot undo your quest edit.
