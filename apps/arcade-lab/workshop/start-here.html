Build your first agents.

Start with one predictable weather tool. Expand to four independent council voices and a judge. Then carry the same ideas into the Claude Agent SDK.

1

Weather · 10 minutes

Predict before you ask.

PREDICTCHANGERUNINSPECT

The starter weather agent has a local tool. Its fixture always returns 72°F and Sunny, while repeating the city you supplied.

Predict

Say the likely temperature and condition aloud before anyone submits a prompt.

Change and run

Change the city in this starter prompt, then ask it in your prepared workspace:

What is the weather in Reykjavík?

Inspect

Compare the tool trace with the reply. Look for the city input and fixed output. An illustrative reply is “Simulated data: Sunny in Reykjavík, 72°F.” It is not live weather.

Hint · Why is Reykjavík sunny?

The fixture is a teaching tool, not a forecast service. It returns the same condition for every city.

Knowledge check: what did you just test?

Correct. The city changes, but the fixture always returns 72°F and Sunny.

Try again. No live weather service is involved in this fixture.

2

Weather · 15 minutes

Shape behavior with instructions.

PREDICTCHANGERUNINSPECT

Predict

What should happen when a weather request does not name a city? Decide whether the agent has enough information to call its tool.

Change

Follow the detailed Eve tutorial to edit agent/instructions.md. Add one rule:

If a weather request has no city, ask which city the user means before using the tool.

Run and inspect

Ask What is the weather in Amsterdam? and inspect the tool input. Then start a fresh conversation and run the incomplete prompt below. Check that no tool call appears before the follow-up question.

What is the weather?
Hint · What should the agent do with the incomplete prompt?

It should ask a follow-up such as “Which city would you like the weather for?” The tool needs a city, so calling it now would invent information.

Which trace best shows your rule worked?

Correct. The instruction closes the information gap before the tool boundary.

Try again. A missing required input should trigger a clarifying question.

3

Council · 20 minutes

One prompt, four independent views.

PREDICTCHANGERUNINSPECT

The Eve council sends the complete prompt once to each of four fixed members. They run independently. Only after all four finish does the judge write a concise answer and score how closely each member agrees with its factual conclusions.

Predict

Work out the answer before running the council. Write the expected number of tables and the calculation.

Change and run

Open the council template in your prepared workspace and submit this verifiable question:

An outdoor workshop has 24 participants. Each table seats 6 people.
How many tables are needed? Explain the calculation in one sentence.

Inspect

Find four separate responses before reading the judge’s summary and four agreement scores. The expected conclusion is four tables because 24 divided by 6 is 4.

Explanation · Why keep members independent?

Each member receives the same complete prompt without seeing another member’s answer. That preserves distinct first responses before the judge compares them.

Stretch prompt · Add judgment after the verifiable check
What are the two most important trade-offs when a small team adopts AI agents?

Predict one point the members may disagree on, then inspect how the judge handles the difference.

What does an agreement score mean?

Correct. Agreement is a comparison with the final summary, not a calibrated probability of correctness.

Try again. A score of 80 is not an 80% chance of truth.

4

Claude Agent SDK · Two follow-up sessions

Keep the behavior across frameworks.

PREDICTCHANGERUNINSPECT

Use the Claude Agent SDK tutorial to recreate the weather tool, then preserve the council’s four actual providers through a parallel Gateway bridge before a Claude SDK judge evaluates their answers.

Eve weatherInstruction + typed tool + trace
SDK weatherSystem prompt + custom tool + messages
Eve councilFour provider-backed members + judge
SDK councilFour Gateway providers + Claude judge

Predict

Before running, predict what should remain the same in the tool data and council conclusions, and what will differ in the SDK message trace.

Change, run, inspect

Port the weather behavior first. Then add the Gateway bridge and Claude judge. Run the same table question and verify four provider results arrive before judging.

Hint · What counts as a faithful port?

Preserve the observable behavior and the same four providers. The bridge changes how the calls are orchestrated; it should not quietly replace provider diversity with four roles on one model.

Are four same-model roles equivalent to four model providers?

Correct. Four contexts can create useful role separation, but they do not reproduce diversity across four providers. This port keeps the providers through the Gateway bridge.

Try again. Output count does not tell you whether the underlying models differ.

5

Exit challenge · 10 minutes

Change one rule. Prove what changed.

PREDICTCHANGERUNINSPECT

Choose either implementation. Change exactly one behavior rule, then use the trace to show its effect. A small change makes cause and effect easier to see.

Weather option: Reply with Celsius as well as Fahrenheit.
Council option: Ask the judge to name one unresolved disagreement.
  1. Write your predicted trace change before editing.
  2. Edit one instruction only.
  3. Run the same prompt as before in your workshop workspace.
  4. Point to the trace evidence. If nothing changed, revise the rule and retry.
Final explanation · What have you built?

You have used instructions to shape decisions, a tool to cross a capability boundary, independent agent runs to create multiple views, and a judge to combine them. Those patterns transfer even when frameworks and models change.

Done means: your rule changed the observed trace or reply, and you can explain why.
