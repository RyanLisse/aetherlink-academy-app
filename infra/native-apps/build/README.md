# Standalone native app image

This recipe currently packages Chat only. The scaffold was generated by the
official standalone CLI with bundled `@agent-native/core@0.182.1`; its
`agent-native.scaffold` metadata and generated lockfile are checked by
`build-context.sh`. Assets, Calendar, Clips, and Content need their own
standalone generation and packaging review. Slides remains on its existing
`infra/poc/slides.Dockerfile` project.

The rollout audit uses BuilderIO/agent-native revision
`adec853eb337cbe0ead48464305d6f30cc07806e` as upstream lineage. That audit
reference is distinct from the generated Chat scaffold identity. The current
Chat source checkout also contains local changes, so its Git `HEAD` must not be
reported as a clean release revision.

Standalone generation resolves `@agent-native/*` to published versions and
records them in `pnpm-lock.yaml`, which keeps the build context small and
portable. The source checkout and lockfile are inputs only. `build-context.sh`
copies a clean context and adds the Dockerfile, `.dockerignore`, and the Chat
auth patch. The patch keeps email/password signup from auto-signing in and
adds `POST /_academy/embed/ticket`, which accepts only a short-lived HMAC
assertion from Academy and returns a same-origin Agent-Native embed start URL.
The assertion contains a deterministic pseudonymous `@academy.invalid`
owner, room and participant identifiers, and the fixed `/home?embedded=1`
target. It never carries an Academy browser token, participant name, or real
participant email. Chat stores a digest of each assertion nonce until expiry,
so replaying the signed mint request cannot create another ticket.

```sh
context_parent="$(mktemp -d /tmp/academy-chat-context.XXXXXX)"
rmdir "$context_parent"
APP=chat \
UPSTREAM_SOURCE_DIR=/tmp/academy-chat-service \
OUTPUT_DIR="$context_parent/source" \
  /path/to/infra/native-apps/build/build-context.sh

docker build \
  --platform linux/amd64 \
  --file "$context_parent/source/Dockerfile" \
  --build-arg SOURCE_REVISION="academy-chat-standalone-core-0.182.1-dirty" \
  --tag academy-chat-native:local \
  "$context_parent/source"
```

For OpenShip, archive and upload this exact context, then compute and retain its SHA-256
alongside the OpenShip deployment ID. OpenShip does not return an archive digest.
The archive digest identifies the uploaded payload; the dirty source checkout state and upstream audit SHA are provenance
only. Keep the digest with the project and deployment record.

The Dockerfile uses a digest-pinned Node 24 base, `corepack pnpm install
--frozen-lockfile`, native build tools for Chat's `node-pty`, `pnpm build`, and
`pnpm prune --prod`. The runtime contains only `.output`, production
dependencies, package metadata, and the checked-in migration entrypoint. It
starts `.output/server/index.mjs` on `0.0.0.0:3000` and exposes the same
`/_agent-native/ping` healthcheck as Slides.

The generated Chat migration entrypoint imports published core JavaScript, so
Node 24 can run it directly without dev-only `tsx` or a source symlink layer:

```sh
docker run --rm \
  --env DATABASE_URL='postgresql://REDACTED' \
  academy-chat-native:local \
  node --experimental-strip-types /app/scripts/migrate-production.ts
```

Apply that migration to Chat's dedicated database before routing traffic. Keep
Better Auth secrets, provider keys, OAuth values, and storage configuration in
OpenShip runtime secrets. The unauthenticated ping is only a readiness gate;
release acceptance still requires authenticated browser signup/sign-in, a real
chat operation, persistence after restart, and exact source identity.

The current operational path builds on the existing server with one active
native-app build at a time and the host's configured resource cap. Keep the
five-app rollout sequential and observe CPU, memory, disk, and build duration
before starting another project. An external GitHub Actions build/export path
is not implemented here and should not be reported as completed. This keeps
cost within the existing server and does not require a second server or public
registry.

Verify the patch against a clean generated Chat template before building:

```sh
infra/native-apps/build/tests/verify-chat-auth-patch.sh
```
